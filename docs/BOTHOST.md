# Атлас и бот на BotHost без GitHub Pages

Ветка `main` содержит единый Dockerfile: Node.js собирает атлас, затем Python-контейнер раздаёт `dist/` на `0.0.0.0:3000` и запускает Telegram-бота. Node.js в работающем контейнере не требуется. HTTPS и публичный домен предоставляет BotHost перед этим HTTP-портом.

## Поля формы BotHost

Dockerfile совместим с обычным сборщиком BotHost без BuildKit. Ошибка `the --mount option requires BuildKit` означает, что используется прежняя версия: пересоберите проект из актуальной `main`. `BUILD_CA_CERT` на BotHost задавать не нужно: это необязательный публичный сертификат доверия для облачной среды разработки.

| Поле                                | Значение                                                                    |
| ----------------------------------- | --------------------------------------------------------------------------- |
| Git URL репозитория                 | `https://github.com/optimur24-gif/starosta-bo.git`                          |
| Ветка                               | `main`                                                                      |
| Bot Token                           | Токен своего бота, вводимый в защищённое поле                               |
| Главный файл                        | `app.py`                                                                    |
| Использовать собственный Dockerfile | Включить                                                                    |
| Веб-интерфейс / админка             | Включить веб-доступ к контейнеру                                            |
| Порт веб-приложения                 | `3000`                                                                      |
| Кастомный домен                     | Можно оставить пустым: по подсказке панели будет выдан автоматический домен |

В дополнительных переменных задайте `BOT_TOKEN` с тем же токеном и `PORT=3000`. Если раньше добавляли `BASE_PATH`, для BotHost установите `/`. Токен остаётся в настройках процесса; в Dockerfile, браузере и репозитории его нет.

## Первый запуск и адрес Mini App

1. Уберите прежний `MINI_APP_URL`, указывающий на GitHub Pages, или оставьте эту переменную пустой. Создайте проект либо пересоберите уже созданный из актуальной ветки `main`. Обычный перезапуск старого контейнера не загружает изменённый Dockerfile.
2. Дождитесь сборки и открытия HTTPS-адреса, который BotHost выдаст проекту. По нему должен открываться атлас, в разделе «3D-череп» — настоящая вращаемая модель. Пока `MINI_APP_URL` отсутствует, сайт работает, а бот ожидает настройки.
3. Скопируйте этот адрес в переменную `MINI_APP_URL`. Нужен полный адрес вида `https://выданный-домен/`, без `#/model`. Не копируйте адрес панели управления BotHost или внутренний адрес с портом `3000`.
4. Перезапустите контейнер после сохранения переменной. В журнале должно появиться «Бот запущен». В личном чате Telegram отправьте `/start`, нажмите «Открыть атлас».

Если адрес уже известен, его можно сразу задать в `MINI_APP_URL`. Команда контейнера — `python app.py`; Dockerfile устанавливает её автоматически. Отдельная команда `python main.py` предназначена для режима, где сайт размещён отдельно.

Остановите ранее запущенную копию этого же бота перед включением нового процесса. Один токен обслуживается одним polling-процессом. Существующий webhook автоматически не удаляется.

## Проверка и ошибки

`/healthz` возвращает состояние сайта и бота. `status: "ok"` означает готовность веб-сервера. Поле `bot` показывает `awaiting_configuration`, `starting`, `running`, `failed`, `stopped` или `disabled`. Готовый сайт продолжает работать, даже если для бота ещё нет адреса или Telegram отклонил токен.

| Ситуация                              | Действие                                                                                 |
| ------------------------------------- | ---------------------------------------------------------------------------------------- |
| Сайт доступен, бот молчит             | Проверить `BOT_TOKEN`, `MINI_APP_URL` и журнал; после изменения переменных перезапустить |
| Кнопка открывает старый GitHub-адрес  | Заменить `MINI_APP_URL` HTTPS-адресом BotHost и перезапустить                            |
| Домен отдаёт 502 или 503              | Проверить завершение сборки, веб-доступ, порт `3000` и запуск `app.py`                   |
| Контейнер содержит прежний код        | Пересобрать из `main`, а не только перезапустить                                         |
| Telegram отклоняет токен: 401 или 404 | Исправить секрет `BOT_TOKEN`                                                             |
| Конфликт polling: 409                 | Остановить другой процесс с тем же токеном                                               |
| Сообщение об установленном webhook    | Отключить прежнюю интеграцию перед использованием polling                                |
| Telegram временно недоступен          | Приложение повторяет подключение; сайт остаётся доступным                                |

Форма и названия полей подтверждены присланными снимками. Сама учётная запись BotHost и работа её внешнего HTTPS-маршрута из этой сессии недоступны. Локальные проверки контейнера и их результаты описаны в [VALIDATION.md](VALIDATION.md).

## Проверка Docker локально или в CI

```bash
docker build -t cranium-bothost .
docker run --rm -p 3000:3000 cranium-bothost
```

Без настроек бота контейнер раздаёт атлас. Для подключения Telegram передайте `BOT_TOKEN` и `MINI_APP_URL` через защищённое окружение хостинга. В CI контейнер запускается без секретов, а браузерные сценарии проверяют реальную геометрию и анимации.
