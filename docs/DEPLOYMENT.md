# Запуск тестовой версии: GitHub Pages + bothost.ru

## 1. Опубликовать Mini App

Отправьте код в `main`, включите GitHub Pages с источником **GitHub Actions** и дождитесь успешного выполнения `.github/workflows/pages.yml`. Адрес берите из результата deployment. Workflow проверяет и публикует только статические файлы `dist/`; токена Telegram в нём нет.

Откройте опубликованную страницу на телефоне. Проверьте поиск `foramen ovale`, карточку клиновидной кости, открытие иллюстрации и тест из пяти вопросов. Перезагрузите страницу и проверьте сохранение отметок. Страница должна открываться по HTTPS без авторизации, недоступной Telegram WebView.

## 2. Создать бота

В официальном `@BotFather` создайте бота командой `/newbot`. Полученный токен поместите в секрет `BOT_TOKEN` на BotHost. Не отправляйте его в чат, не добавляйте в Git и не используйте переменные `VITE_*`: они попадают в браузерную сборку.

Если используете существующего бота, сначала убедитесь, что его не обслуживает другой процесс. Эта версия использует long polling. Код проверяет `getWebhookInfo` и отказывается запускаться при установленном webhook; он не удаляет чужую конфигурацию.

## 3. Разместить процесс на BotHost

В Python-проект bothost.ru передайте репозиторий через доступный в вашем тарифе способ: импорт GitHub или загрузку файлов. Для процесса бота достаточно `main.py` и `requirements.txt`. Фронтенд, `node_modules` и `dist` боту не нужны.

Требования к среде:

- Python 3.11 или новее; рекомендуемая версия 3.12.
- Постоянно работающий процесс `python main.py`.
- Исходящие HTTPS-запросы к `api.telegram.org`.
- Секрет `BOT_TOKEN` и обычная переменная `MINI_APP_URL` с рабочим адресом из шага 1.

Если доступен Docker, используйте прилагаемый Dockerfile. Образ запускает только бота от непривилегированного пользователя. Python-зависимостей и входящего HTTP-порта для polling не требуется.

До включения постоянного процесса можно запустить `python main.py --check`. Он вызывает только `getMe` и `getWebhookInfo`. Затем запустите `python main.py`. При обычном старте бот устанавливает команды и кнопку меню через Telegram API, после чего ожидает личные сообщения.

Подключение к самому BotHost из этой машины ограничено прокси. Шаги выше описывают требования готового проекта; конкретные названия кнопок панели, поддержка GitHub-импорта и Docker зависят от текущего интерфейса и тарифа и здесь не проверены.

## 4. Проверить в Telegram

Отправьте своему боту `/start` в **личном чате**. Нажмите **«Открыть атлас»**. Откройте кость, вернитесь встроенной кнопкой Telegram «Назад», пройдите тест. Ответы в групповых чатах отключены, поскольку кнопки типа `web_app` предназначены для личных чатов.

Бот самостоятельно задаёт стандартную кнопку меню. Для показа кнопки запуска в профиле бота дополнительно настройте Main Mini App в официальном интерфейсе BotFather, указав тот же HTTPS-адрес. Это действие выполняет владелец бота; приложение не изменяет профиль через неофициальные API.

Приложение не читает имя, фотографию или `initData` пользователя и не отправляет результаты на сервер. Если позже появятся аккаунты, платежи или серверный прогресс, потребуется серверная проверка подписи Telegram `initData`.

## Ошибки запуска

| Наблюдение                                             | Действие                                                                                                        |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Процесс завершился с кодом 2 и сообщением о переменной | Задать `BOT_TOKEN` и `MINI_APP_URL` в окружении процесса                                                        |
| `MINI_APP_URL` не принят                               | Нужен публичный HTTPS-адрес без встроенного логина/пароля                                                       |
| Установлен webhook                                     | Остановить прежнюю интеграцию и сознательно отключить её webhook                                                |
| Telegram вернул 409                                    | Остановить вторую копию polling; один токен — один процесс                                                      |
| Telegram вернул 401/404                                | Проверить токен в защищённой конфигурации                                                                       |
| Временная ошибка 429/503                               | Бот применяет паузу и повтор; проверить доступ к Telegram, если ошибка постоянная                               |
| Pages отдаёт 404                                       | Включить Pages, дождаться deployment, проверить ветку и путь репозитория                                        |
| После обновления пропали изображения                   | Проверить `BASE_PATH` и не переносить только `index.html`: нужен весь `dist/`                                   |
| Прогресс не сохраняется                                | Проверить доступность хранилища WebView; при запрете приложение работает до закрытия без постоянного сохранения |

Для первого запуска не нужны GitHub Secrets с Telegram-токеном: Pages не обращается к Bot API. Токен нужен только процессу на BotHost.

Официальная документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Bot API](https://core.telegram.org/bots/api), [GitHub Pages с Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [BotHost](https://bothost.ru/).
