Всего проходят 59 различных проверок: 21 TypeScript, 22 Python и 16 браузерных сценариев. Проверка пути Pages повторяет браузерные сценарии для другого пути. Пропущенных тестов нет.

Браузерные сценарии контролируют фактическое количество отрисованных треугольников, выбор и изоляцию сторон костей, фильтры 8/14/22 костей, сборку/разборку, изменение камеры, связь 3D-метки с термином, поиск, оригинальные иллюстрации, завершение теста и локальное сохранение прогресса.

Python-проверки делают настоящие HTTP-запросы и запускают отдельный процесс: проверяют MIME и бинарные ответы, HEAD, запрет изменения файлов, обходы путей и симлинки, CSP для Telegram, монтаж по подпути, сохранение сайта без MINI_APP_URL, обработку SIGTERM и совместную работу веб-сервера с имитированным polling. Ошибка токена не останавливает сайт; временная недоступность Telegram при старте приводит к повтору подключения. Telegram API в этих тестах имитируется.

После сообщения BotHost `the --mount option requires BuildKit` из Dockerfile удалены RUN --mount и COPY --chmod. Образ успешно собран с DOCKER_BUILDKIT=0; CI также явно использует этот режим. Права на файлы устанавливаются обычным RUN chmod. Для доверенного прокси этой облачной среды публичный CA передаётся необязательным аргументом BUILD_CA_CERT, считываемым из уже доверенного файла NODE_EXTRA_CA_CERTS. Это публичный сертификат, не токен и не секрет; на BotHost он не нужен. HTTPS-проверка и контрольные суммы npm сохранены, временный CA удаляется после установки, а npm-кэш стадии сборки не копируется в runtime. В обычной среде достаточно docker build -t cranium-bothost . без дополнительного CA.

## Облачная конфигурация

Сохранённый install_script содержит установку, проверку данных, тесты, сборку и браузерные сценарии. start_skill обновлён для Python-сервера и единого Docker-контейнера: включает готовность HTTP, проверку манифеста, тесты контейнера и доверенный CA при сборке за прокси. Сохранение конфигурации не выполняет её публикацию, миграцию машины или внешний запуск BotHost.

## Удалённые проверки и публикация

Первоначальная версия отправлена в main 19 октября 2026 года: её удалённый [CI прошёл](https://github.com/optimur24-gif/starosta-bo/actions/runs/39250562212). В первом [workflow Pages](https://github.com/optimur24-gif/starosta-bo/actions/runs/39250562361) задание build прошло, артефакт github-pages создан: 7,98 МБ. Тогда deploy остановился на `Get Pages site failed: Not Found`, поскольку Pages ещё не был включён. Пользователь затем выбрал GitHub Actions в настройках Pages; результат последующей публикации здесь не подтверждён. Основной вариант теперь не зависит от Pages.

Текущий CI собирает Docker-образ, запускает его без секретов и направляет браузерные сценарии прямо в контейнер. Результаты прежнего удалённого CI относятся к первоначальной версии; локальные результаты нового контейнера приведены выше.

Для внешнего запуска используется [инструкция BotHost](BOTHOST.md): app.py, собственный Dockerfile, веб-доступ к порту 3000, затем выданный HTTPS-адрес в MINI_APP_URL. Форма подтверждена присланными снимками; доступа к аккаунту BotHost в этой сессии нет. Обновление опубликованного кода требует пересборки проекта из main.

Из этой машины запросы к Telegram и BotHost ранее отклонял прокси: `Tunnel connection failed: 403 Forbidden`, до проверки токена. Секрет в файлы не включён. Сохранённый сетевой черновик сам по себе не меняет доступ текущей машины. Это ограничение не относится к запуску контейнера в аккаунте BotHost.

## Что не подтверждено

- Внешнее HTTPS-развёртывание на BotHost и работа его reverse proxy: локальная проверка контейнера не является проверкой внешнего домена.
- Реальные запросы с токеном к Telegram, получение команды от пользователя и открытие приложения внутри Telegram. Для проверки учётной записи и webhook предусмотрена команда `python3 main.py --check`.
- Экспертная медицинская рецензия: 92 структуры имеют перенесённые 3D-метки, остальные 134 доступны в каталоге без придуманных координат. Геометрическая регистрация и программные тесты не подтверждают медицинскую точность каждой метки.
- Первичный PDF FIPAT напрямую недоступен из-за сетевой политики; источники, варианты терминов и ограничения описаны в ANATOMY.md.

Предупреждение Vite о размере отложенного Three.js-модуля не является ошибкой сборки. Библиотека загружается отдельно; геометрия хранится в проекте и не зависит от внешнего 3D-CDN.
